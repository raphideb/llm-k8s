## Setup Script Commands

```bash
./setup.sh configure      # Configure model path or download model
./setup.sh preflight      # Check system requirements
./setup.sh nvidia         # Install NVIDIA Container Toolkit
./setup.sh device-plugin  # Deploy NVIDIA device plugin
./setup.sh deploy         # Deploy llama.cpp server
./setup.sh opencode       # Install and configure opencode
./setup.sh test           # Test the deployment
./setup.sh status         # Show current status
./setup.sh cleanup        # Remove llama.cpp deployment
./setup.sh all            # Full installation

# Options
./setup.sh --dry-run <cmd>  # Preview without executing
```

## Configuration File (.llama-config)

Generated by `./setup.sh configure`. Contains:

```bash
MODELS_PATH="/path/to/models"    # Directory containing .gguf files
MODEL_FILE="model-name.gguf"     # Selected model filename
NODE_IP="x.x.x.x"                # Kubernetes node IP
```

## llama-server Parameters

```bash
--model /models/${MODEL_FILE}
--host 0.0.0.0
--port 8080
-ngl 99                # All layers on GPU
--ctx-size 32768       # 32K context
-b 2048                # Batch size
-ub 512                # Micro-batch size
--threads 8            # CPU threads
--flash-attn on        # Flash Attention enabled
--metrics              # Prometheus metrics
```

## Known Issues and Solutions

### 1. llama.cpp Argument Names Changed

Recent llama.cpp versions use different argument names:

| Old | New |
|-----|-----|
| `--n-gpu-layers` | `-ngl` |
| `--n-batch` | `-b` or `--batch-size` |
| `--n-ubatch` | `-ub` or `--ubatch-size` |
| `--flash-attn` | `--flash-attn on\|off\|auto` |

### 2. Model Load Time

First request after deployment takes 30-60 seconds (model loading + warmup).

### 3. WSL2 GPU Passthrough

Do NOT install NVIDIA drivers inside WSL2. GPU access uses Windows driver via `/dev/dxg`.
